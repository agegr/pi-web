# Spec-001：工作区 Markdown 所见即所得实时编辑

**日期：** 2026-09-12  
**状态：** 需求已确认，待开发

> 本任务只记录需求，不包含代码实现。

## 背景

当前项目可以在工作区的文件面板中查看 Markdown 文件，并使用现有能力渲染 Markdown 内容，但还缺少符合日常写作习惯的编辑体验。

用户希望直接在工作区文件面板中编辑已有的 `.md` 文件：编辑内容时立即看到渲染效果，修改结果自动保存回原文件；如果文件被外部程序修改，系统需要实时感知并进行冲突处理。

## 目标

在现有文件查看能力上增加 Markdown 所见即所得编辑能力，满足以下核心体验：

- 点击已有 `.md` 文件后，在当前文件面板直接进入编辑状态；
- 编辑和预览在同一个单栏中完成，不使用左右分栏；
- 标题、粗体、列表等 Markdown 内容以渲染后的样式呈现，尽量隐藏源码符号；
- 用户输入后实时更新显示结果，并自动保存到原文件；
- 复用当前项目已有的 Markdown 渲染能力，不重新设计一套 Markdown 语法或预览规则；
- 检测文件的外部修改，避免静默覆盖用户正在编辑的内容。

## 需求边界

### 包含

- 编辑工作区中已经存在的 `.md` 文件；
- 单栏所见即所得编辑；
- 编辑过程中的实时渲染；
- 修改后的自动保存；
- 保存失败时显示错误，并保留当前编辑内容供用户重试；
- 文件外部修改的实时检测与冲突提示；
- 复用当前 Markdown 渲染中已有的能力，包括：
  - 标题、段落、粗体、斜体、列表、引用等基础内容；
  - 代码块；
  - Mermaid 图表；
  - 图片；
  - 本地文件链接；
  - frontmatter（文件头元数据）。
- 继续遵守当前工作区文件访问权限和路径安全规则。

### 不包含

- 新建 Markdown 文件；
- 重命名、删除或移动文件；
- `.markdown` 等其他扩展名；
- 移动端编辑适配；
- 多人协同编辑；
- 云端同步；
- 独立的 Markdown 工具栏或富文本排版系统；
- 为代码块、Mermaid、frontmatter、图片和文件链接新增独立编辑器；
- 自动合并两个来源同时产生的修改；
- Markdown 历史版本管理。

## 交互规则

### 进入编辑

1. 用户在工作区文件面板点击已有 `.md` 文件。
2. 文件在当前文件面板中打开并进入编辑状态。
3. 不新增独立编辑页面，也不要求用户在源码模式和预览模式之间整页切换。

### 编辑与实时预览

1. 编辑器使用单栏布局。
2. 用户输入后，当前内容立即按照项目现有 Markdown 渲染规则更新。
3. 所见即所得内容应尽量显示最终样式，Markdown 标记符号只在编辑需要时出现或被弱化处理。
4. 代码块、Mermaid、图片、文件链接和 frontmatter 继续使用项目现有的显示和处理能力。
5. 编辑或保存过程中不得静默丢失上述复杂内容。

### 自动保存

1. 用户修改内容后自动保存到当前文件的原路径。
2. 自动保存可以采用短暂防抖，避免每个字符都产生一次文件写入；防抖时长属于实现参数，建议默认约 500ms。
3. 保存成功时不显示额外的成功提示。
4. 保存失败时显示明确错误信息。
5. 保存失败后，用户当前的编辑内容必须保留，不得恢复成旧文件内容，并应允许后续重试。
6. 自动保存不得创建新文件，也不得修改其他文件。

### 外部修改与冲突

1. 文件没有本地未保存修改时，如果外部程序修改了文件，编辑器应实时重新读取并更新内容。
2. 文件存在本地未保存修改时，如果检测到外部修改，不能直接用外部内容覆盖本地编辑内容。
3. 此时应提示用户发生冲突，并保留本地编辑内容。
4. 用户至少可以选择：
   - 重新加载外部文件内容，放弃本地修改；
   - 保留本地修改并覆盖保存外部内容。
5. 第一版不做自动合并。

## 验收标准

- [ ] 点击工作区中已有的 `.md` 文件后，可以在当前文件面板直接编辑。
- [ ] 编辑器为单栏布局，不出现左右分栏预览。
- [ ] 编辑时标题、粗体、列表等内容以接近最终渲染效果的样式显示。
- [ ] 修改内容后，渲染结果实时更新，不需要手动刷新或切换页面。
- [ ] 修改内容会自动保存回原 `.md` 文件。
- [ ] 重新打开该文件后，能够看到上次成功保存的内容。
- [ ] 保存失败时，界面显示错误信息，且当前编辑内容不丢失。
- [ ] 外部修改会被实时感知。
- [ ] 没有本地修改时，外部修改可以自动更新到编辑器。
- [ ] 存在本地修改时，外部修改会触发冲突提示，不会静默覆盖本地内容。
- [ ] 代码块、Mermaid、图片、本地文件链接和 frontmatter 仍按当前项目能力正常显示并在保存后保留。
- [ ] 非 `.md` 文件的现有查看行为不受影响。
- [ ] 不要求移动端支持。

## 主要场景

### 场景一：编辑并自动保存

1. 用户从文件面板打开 `notes/today.md`（工作区中的 Markdown 文件）。
2. 文件在当前面板进入所见即所得编辑状态。
3. 用户修改标题和正文。
4. 内容实时更新渲染结果。
5. 用户停止输入后，系统自动保存文件。
6. 用户重新打开文件，看到已保存的修改。

### 场景二：保存失败

1. 用户正在编辑 Markdown 文件。
2. 自动保存时发生权限、文件系统或网络请求错误。
3. 界面显示保存失败原因。
4. 用户当前编辑内容继续保留。
5. 用户修复问题后，可以再次触发自动保存或重试保存。

### 场景三：没有本地修改时发生外部修改

1. 用户打开 Markdown 文件但没有修改内容。
2. 用户通过编辑器外的程序修改该文件。
3. 系统检测到文件变化。
4. 编辑器实时加载外部最新内容。

### 场景四：存在本地修改时发生冲突

1. 用户打开 Markdown 文件并产生了未保存修改。
2. 其他程序同时修改同一个文件。
3. 系统检测到外部变化并暂停覆盖保存。
4. 系统提示发生冲突，同时保留用户当前编辑内容。
5. 用户选择重新加载外部内容，或确认用本地内容覆盖保存。

## 内容保真要求

- 编辑器不得因为进入编辑状态而改写文件内容。
- 保存时必须保留未被用户修改的内容。
- 代码块、Mermaid、图片地址、本地文件链接和 frontmatter 不得因为编辑基础文本而丢失。
- 不要求第一版保证 Markdown 源码的空格、换行或标记写法完全保持不变，但不得改变用户未编辑内容的实际语义。

## 异常与安全要求

- 只允许编辑工作区允许访问范围内的已有普通文件。
- 文件不存在、不是普通文件、不是 `.md` 或无权访问时，不进入编辑状态，并显示可理解的错误信息。
- 超出当前文件读取或编辑能力限制的文件，应保持只读或提示无法编辑，不能截断后覆盖原文件。
- 保存请求失败、超时或返回异常时，不得清空编辑器内容。

- 外部修改的自动刷新；
- 本地修改与外部修改同时存在时的冲突保护；
- 复杂 Markdown 内容的渲染和保存后保真；
- 非 Markdown 文件行为不受影响；
- 桌面端文件面板主要编辑流程的端到端测试。
