# Spec-002：可切换的主区域与右侧工作区

**日期：** 2026-09-12
**状态：** 已实现，待浏览器人工验收

## 背景

现有界面把聊天窗口和文件编辑窗口直接当作两块固定内容来布局。右侧文件面板同时承担了“文件编辑内容”和“右侧可缩放工作区”两个职责。

这会导致切换后逻辑混乱：文件编辑窗口移到左边时，关闭、缩放、恢复宽度、窄屏覆盖层等行为仍然绑定在文件组件上；顶部按钮也会跟着聊天窗口或文件窗口移动。

本需求将**内容**与**布局角色**拆开：聊天和编辑窗口是内容；主区域与右侧工作区是固定的布局角色。

## 目标

- 中间的主区域和右侧工作区始终是固定的位置角色；
- 切换时只交换聊天窗口和编辑窗口所占据的角色，不交换整套布局轨道；
- 三个顶部控制按钮从内容面板中分离，始终锚定在各自的结构边缘；
- 右侧工作区的关闭、展开、缩放、宽度恢复、窄屏覆盖层等能力，复用于当前承载在右侧的内容；
- 聊天和编辑的业务能力保持独立，不把文件编辑逻辑塞进聊天窗口，也不把聊天逻辑塞进文件编辑窗口。

## 术语

| 术语 | 含义 |
| --- | --- |
| 侧边栏 | 左侧会话列表、项目列表和文件树。 |
| 主区域 | 位于侧边栏右侧、右侧工作区左侧的主要内容区域；占用剩余宽度。 |
| 右侧工作区 | 固定在界面右侧的次级可缩放区域；可以关闭、展开和恢复宽度。 |
| 编辑窗口 | 文件 Tab、文件预览/编辑、终端等内容。 |
| 聊天窗口 | 会话消息、流式输出、输入框及其会话状态。 |
| 切换 | 交换聊天窗口与编辑窗口所占据的“主区域 / 右侧工作区”角色。 |

“固定位置”指固定在结构锚点，不是把按钮锁死在某个像素坐标；侧边栏调整宽度时，贴着侧边栏的按钮应随该边缘移动。

## 布局模型

桌面端保留三条固定轨道：

```text
侧边栏 │ 主区域 │ 右侧工作区
```

初始状态：

```text
侧边栏 │ 聊天窗口 │ 编辑窗口
```

切换后：

```text
侧边栏 │ 编辑窗口 │ 聊天窗口
```

切换后编辑窗口成为主工作区，聊天窗口成为右侧工作区。右侧工作区仍在右边，主区域仍在中间；不得改为“编辑窗口在左、聊天窗口在右”之外的另一套网格布局，也不得交换按钮和分隔线的位置。

## 三个独立控制按钮

按钮必须位于独立的控制层，不能作为聊天窗口或编辑窗口标题栏的子元素。

| 按钮 | 结构锚点 | 作用 | 切换后的要求 |
| --- | --- | --- | --- |
| 隐藏侧边栏 | 侧边栏右边缘 | 收起/展开侧边栏 | 始终贴着侧边栏边缘，不随聊天或编辑内容移动。侧边栏收起后仍需保留可见的边缘控制位，以便重新打开。 |
| 隐藏工作区 | 主区域与右侧工作区的分界线 | 收起/展开当前右侧工作区 | 始终位于该结构分界线；只控制当前右侧工作区，不固定控制编辑窗口。 |
| 交换聊天区与工作区 | 界面最右边缘 | 交换两种内容的布局角色 | 始终位于最右边缘，不随右侧工作区内容移动。 |

切换只更换内容归属：

```text
mainContent <-> secondaryWorkspaceContent
```

它不得移动、重建或重新归属三个控制按钮。

## 右侧工作区复用逻辑

右侧工作区的状态属于位置角色，而不是文件编辑内容。建议使用概念状态：

```text
isSwapped                 // 当前是否已切换
secondaryWorkspaceOpen    // 右侧工作区是否展开
secondaryWorkspaceWidth   // 右侧工作区宽度
```

### 展开、关闭和恢复

1. “隐藏工作区”始终收起当前右侧工作区。
2. 未切换时，收起的是编辑窗口，聊天窗口扩展为主区域。
3. 已切换时，收起的是聊天窗口，编辑窗口扩展为主工作区。
4. 再次展开时恢复用户上次设置的右侧工作区宽度。
5. 关闭工作区只隐藏该区域，不销毁其中的聊天、编辑器、终端或文件 Tab 状态。
6. 当右侧工作区关闭时仍保留可用于重新展开的控制位；用户不能因为关闭面板而失去打开入口。

### 缩放

1. 分隔线始终位于主区域与右侧工作区之间。
2. 拖动分隔线时，改变的是右侧工作区宽度；主区域自动占用其余空间。
3. 支持现有鼠标/触摸拖动、键盘方向键调整、`Shift` 加大步长和双击恢复默认宽度。
4. 宽度继续受最小宽度、最大宽度、侧边栏宽度和视口宽度限制；窗口尺寸或侧边栏宽度变化后必须重新校正。
5. 已切换时，拖动方向、键盘方向和无障碍文本必须反映“右侧工作区”的实际边界，不得继续描述为“文件面板”。
6. 宽度持久化的键名和语义应描述右侧工作区，而不是文件面板；切换后仍恢复同一条右侧工作区轨道的宽度。

### 动画、遮罩和无障碍

1. 展开、收起和缩放沿用现有过渡动画；拖动期间关闭过渡，避免内容抖动。
2. 窄屏工作区的遮罩、点击遮罩关闭、焦点处理和动画也属于右侧工作区逻辑，不能硬编码为文件编辑器专属。
3. 分隔线保留 `separator` 角色、当前像素宽度、最小/最大值和键盘操作能力。
4. 按钮的 `aria-controls`、`aria-expanded`、提示文案和标题应使用“右侧工作区”等位置术语；当右侧承载聊天时，不应继续显示“隐藏文件面板”。

## 内容特有逻辑

布局能力可复用，但内容业务不可混用。

| 内容 | 保留的专属能力 | 位置角色变化后的规则 |
| --- | --- | --- |
| 编辑窗口 | 文件 Tab、文件查看/编辑、Markdown 编辑、Diff、终端、文件监听、选中代码后引用。 | 无论位于主区域还是右侧工作区，仍保留这些能力。编辑窗口位于主区域时，文件监听与终端运行状态必须继续有效。 |
| 聊天窗口 | 会话消息、流式输出、输入框、草稿、滚动位置、引用选中内容、会话控制。 | 无论位于主区域还是右侧工作区，仍保留聊天能力；切换不得重置聊天滚动位置、输入草稿或流式状态。 |

### 文件与终端触发规则

1. 未切换时，打开文件或终端 Tab 自动展开右侧编辑工作区。
2. 已切换时，编辑窗口已经是主工作区；打开文件或终端只需激活对应 Tab，不应错误展开右侧聊天工作区。
3. 未切换时，关闭最后一个文件/终端 Tab 可以收起右侧编辑工作区。
4. 已切换时，关闭最后一个文件/终端 Tab 不得关闭主工作区；应显示空编辑工作区状态。
5. 文件查看器的监听开关、代码引用能力，以及终端的运行/暂停判断，必须依据“编辑窗口当前是否可见”，不得继续以“右侧工作区是否打开”作为唯一条件。

## 响应式规则

### 宽屏桌面（>= 960px）

- 同时显示侧边栏、主区域和右侧工作区；
- 支持切换、关闭/展开与拖动缩放；
- 三个控制按钮保持独立结构锚点。

### 窄桌面（641px–959px）

- 主区域优先保持可用宽度；右侧工作区采用现有覆盖层模式；
- 覆盖层承载当前右侧工作区内容，切换后可以承载聊天窗口；
- 遮罩和关闭入口仍需可用，且控制按钮不应被内容标题栏挤压或遮挡。

### 手机（<= 640px）

- 侧边栏继续作为抽屉；右侧工作区以全屏覆盖层显示；
- 由于屏幕无法同时展示主区域与右侧工作区，不提供桌面式的左右交换；交换按钮隐藏或禁用，并提供清楚的不可用说明；
- 聊天输入、文件编辑和终端继续遵守现有移动端安全区与虚拟键盘高度处理。

## 当前实现需要解除的错误绑定

现有实现中的 `rightPanelOpen`、`rightPanelResizer`、`file-panel`、`pi-right-panel-width`、文件监听开关、终端激活状态和“隐藏文件面板”文案，均不同程度地将右侧工作区逻辑绑定在编辑窗口上。

实现本规格时应：

- 将右侧工作区状态从编辑窗口内容中抽离；
- 让主区域和右侧工作区成为稳定容器；
- 根据 `isSwapped` 将聊天或编辑内容放入对应容器；
- 让控制层引用稳定的容器，而不是引用会被切换的内容组件；
- 保持内容组件挂载身份稳定，避免交换时丢失聊天和编辑状态。

## 验收标准

- [ ] 初始状态为“中间聊天、右侧编辑”。
- [ ] 切换后为“中间编辑、右侧聊天”。
- [ ] 切换不会移动侧边栏、主区域/右侧工作区分界线、最右边缘的控制位。
- [ ] 三个按钮不属于聊天窗口或编辑窗口标题栏，且始终位于规定的结构锚点。
- [ ] 未切换时，关闭右侧工作区隐藏编辑窗口；已切换时，关闭右侧工作区隐藏聊天窗口。
- [ ] 收起右侧工作区后，当前主区域占满可用宽度；重新展开后恢复上次宽度。
- [ ] 分隔线拖动、键盘调整、双击重置、宽度持久化和视口校正，对当前右侧工作区均有效。
- [ ] 已切换时，编辑窗口在主区域中仍会刷新文件、保持终端运行并支持代码引用。
- [ ] 已切换时，打开文件/终端不会错误展开右侧聊天工作区。
- [ ] 已切换时，关闭最后一个编辑 Tab 不会关闭主编辑工作区。
- [ ] 聊天草稿、滚动位置、流式状态，和编辑器 Tab、终端、文件状态在切换前后均保留。
- [ ] 窄桌面和手机端不出现按钮重叠、无法关闭的覆盖层或无意义的左右交换。

## 不包含

- 改变聊天消息、Agent 运行、文件读写或终端本身的业务能力；
- 新增另一套文件编辑器、聊天输入框或 Tab 系统；
- 多窗口、多用户协作或跨设备同步布局；
- 在本规格落地前删除现有未提交功能或重置现有工作区改动。

## 落地记录（2026-09-12）

- 使用固定的 `main / separator / secondary` 网格轨道；切换只改变聊天和编辑器的网格角色，不再反转列或拖动分隔线的位置。
- 三个桌面端按钮独立于聊天和编辑器标题栏：侧边栏按钮跟随侧边栏边缘，工作区按钮跟随固定分界线，交换按钮固定在最右边。
- 当前主工作区的顶栏会为侧边栏边缘按钮预留安全区：聊天在主区域时保护“完整历史”等聊天操作，编辑器在主区域时保护首个文件 Tab；交换内容不会改变这条规则。
- 两个会随分隔线移动的固定按钮直接读取拖动时实时更新的 CSS 宽度变量，避免等待 React 在松开指针后才提交最终宽度而出现延迟跟随。
- 右侧工作区的展开、关闭、宽度、分隔线与遮罩现在都以位置角色为准；编辑器位于主区域时，文件监听、代码引用和终端仍保持启用。
- 已切换时，打开或关闭文件/终端 Tab 不会误开或关闭右侧聊天工作区。
- 已通过 TypeScript 检查、关联组件测试和本次改动范围的 ESLint。全量 ESLint 会扫描现有 `.next-backups` 大型缓存，未作为本次验收门槛。
- 使用阻止 Service Worker 的全新浏览器上下文完成宽屏位置测量：切换前后侧边栏按钮、工作区按钮和交换按钮坐标不变；编辑器与聊天窗口按预期互换主区/右侧工作区角色。最终仍建议在 `30141` 刷新后的页面中做一次人工视觉确认。
