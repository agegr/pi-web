pi-web 聊天功能界面基线与优化对比

记录日期：2026-09-11。本清单依据当前仓库源码确认，未对每个动态状态逐一取得运行截图；它是功能和交互基线，不等同于经过浏览器验证的视觉缺陷报告。优化方向属于建议，尚未实施。

聊天相关功能大多是同一主工作台中的空白态、消息区、输入区、顶部下拉面板、浮层和消息内嵌卡片，不是各自拥有独立 URL 的页面。以下按功能界面编号，便于优化前后使用相同状态对比。

优化前后对比与验收建议

  1. 输入与运行控制（C04/C06）：固定同一会话，记录闲置、流式生成、排队两条消息、停止、模型错误和移动端更多菜单六组状态。验收发送、追加、停止的作用是否无需悬停即可理解；不得在比较中改变会话内容来掩盖布局差异。
  2. 消息阅读层次（C02/C03/C15/C17）：使用包含工具、思考、最终答案、文件结果的同一轮会话，记录运行中、完成后折叠、过程展开。比较最终答案可见面积，以及找回指定工具结果所需操作数；具体数值应实测。
  3. 会话导航（C22/C23/C24）：分别建立长对话、多分支、多 Agent 样本。验证用户能否识别当前会话、当前分支、运行中的 Agent，并完成定位；桌面和移动端独立比较。
  4. 开发信息面板（C25/C26）：覆盖长系统提示词、多工具、复杂参数、未加载、加载中和空状态。比较可读行长、查找目标信息的操作数、窄屏布局与滚动范围。
  5. 扩展界面（C27–C30）：覆盖无扩展、多个 Widget、长状态、四种原生弹窗、自定义面板。没有实际扩展请求的动态状态应明确标为“源码确认，未取得运行截图”，不得用伪造数据截图冒充生产实况。
  6. 错误反馈（C31）：用可控的真实错误复现样本，检查错误归属、恢复入口与通知消失行为。对比时保留相同失败原因，不能只展示正常状态。

建议先处理输入与运行行为、消息阅读层次，再处理导航及信息面板，最后统一扩展和错误反馈。这是基于功能重要性的设计建议，不代表已通过用户研究或运行测评证明优先级。
