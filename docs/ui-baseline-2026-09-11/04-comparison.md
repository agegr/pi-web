# Pi Web 界面优化对照与验收

基准：2026-09-11 当前工作区。右列为建议，尚未实施；不是两个已实现版本的 A/B 测试。当前未提供新版设计，因此“优化后截图”和测量结果保留为空，不能推断改版已完成。

## 建议优先处理的对照项

| 优先级 | 对应界面 | 当前事实 | 建议优化方向 | 优化后验收 |
|---|---|---|---|---|
| P1 | W01/C01 首次使用 | 无项目时是两步文字提示；选定项目后显示品牌与输入器；无已配置模型时模型选择入口不完整 | 做清晰的项目、模型、开始对话三步引导与完成反馈 | 首次用户不用阅读 README 能完成进入可发送状态；记录实际点击数与失败点 |
| P1 | C04/C06/C13 输入与运行 | 输入区同时承载附件、推理、预设、压缩、提示音；运行时追加输入分引导/后续 | 分清输入动作与会话配置，发送/停止位置稳定；追加操作直白解释 | 空闲、生成、排队、停止、错误、移动端六种状态均可辨认主要动作 |
| P1 | C02/C03/C15/C17 回答阅读 | 过程可以折叠，正文与消息内用量、工具卡共存 | 保留最终结果优先，过程摘要显示失败和文件产物线索 | 同一会话同一滚动位置对比正文可见面积；过程可找回，无错误被折叠遗漏 |
| P1 | MOD-00/06/07 保存语义 | 自定义模型用底部保存；认证单独提交；常规设置即时生效 | 明示每个操作保存范围、未保存标记、生效状态 | 用户可以区分“已连接”“草稿未保存”“已保存”，切页不会误以为全部生效 |
| P1 | W15 移动端 | 顶部和输入区各有更多入口；设置页签变选择器；文件覆盖聊天 | 清楚区分入口作用，返回主聊天明显；确保软键盘弹起后的可操作区域 | 390×844、横屏、键盘弹起、长内容、文件打开分别验证；不遮挡发送/关闭 |
| P2 | W03/W05/W08 项目/会话 | 项目路径、worktree、会话树与文件树同在侧栏 | 项目/分支/会话/文件四层层次明确，长路径使用可区分短名 | 多项目、同名目录、多 worktree 中当前目标可唯一识别 |
| P2 | F06/F07/F08 文件阅读 | 右栏较窄；Source/Preview/Diff 和图标工具并列；图12为 1280px 桌面截图 | 在有限宽度突出模式和正文；折叠次要元信息 | 代码长行、表格、Markdown、长路径没有遮挡；切标签恢复阅读状态 |
| P2 | SET/SKL/PLG 文案一致性 | 简体中文模式仍出现 Source、Examples、global、project、No plugins configured 等 | 统一产品层文案；API、Provider ID、代码保留原文 | 三种语言逐页检查，避免按钮和状态夹杂未翻译说明 |
| P2 | PLG-01 诊断 | 诊断细节主要放在 title；会话重载独立按钮 | 可展开诊断与复制；把启用、安装、已载入当前会话分开 | 在触屏上也可读完整诊断；未重载不会显示为当前会话已生效 |
| P2 | SKL-01 技能开关 | 开关影响模型提示词可见性，手动调用仍存在 | 常驻说明开关真实含义 | 关闭后 UI 文案不声称卸载或完全禁用；保留手动调用规则 |
| P2 | W10/F05 危险操作 | 删除会话、覆盖上传、移除 worktree 的确认形式不同 | 统一对象、影响、主次按钮表达，保留各自边界条件 | 每项均能准确识别操作对象；取消不产生变更 |
| P3 | C22/C23/C24 导航 | Minimap、分支树、Agent 面板各自解决不同导航问题 | 统一入口命名，显示当前对象与关系；增加触屏替代 | 固定长对话样本能回到目标轮次、分支与子任务 |
| P3 | C25/C26 开发信息 | 系统提示词只读滚动；工具定义主从布局 | 搜索、复制、章节导航按需展开 | 长提示词与多工具检索可用，空态与加载态明确 |
| P3 | C27–C31 扩展与错误 | 动态扩展状态、Widget、交互弹窗、消息错误等多种形态 | 建立共同状态表达和恢复动作 | 扩展四类交互弹窗、长输出、失败、多个 Widget 均有可读布局 |

以上优先级是基于主流程影响和源码结构的建议，没有用户测试数据支撑时间节省百分比。不要将其当作已量化的收益。

## 设计基础与验收边界

现有 [globals.css](../../app/globals.css) 定义了背景、面板、悬停、选中、边框、正文/次级/弱化文字、强调色、消息背景等变量；浅色强调色 `#2563eb`，深色 `#60a5fa`，正文基础字号 14px。组件局部还使用 10–12px 文字和行内颜色。优化应先复用和整理现有变量，不新增互相竞争的主题系统。

建议评审顺序：信息架构 → 主流程操作 → 内容密度与排版 → 反馈状态 → 移动端 → 颜色和图标细节。每个功能保留原有触发条件与操作结果，除非另行明确批准行为变化。

本次仅文档和截图归档：已观察到的页面不等于所有按钮功能经过测试；没有执行模型请求、凭据保存、安装/卸载、文件覆盖、删除或 worktree 创建。代码测试、类型检查和构建不属于本次纯文档变更验证；未运行，亦未宣称通过。
