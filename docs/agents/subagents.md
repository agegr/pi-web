# Subagents

- Sub-agent delegation is owned by the user-installed `pi-subagents` package, a normal pi extension that is not a Pi Web dependency. Its tools load with every session like any other installed package; Pi Web neither bundles it nor strips, suppresses, or manages it. Pi Web ships no sub-agent engine and provides no feature switch for this.
- Legacy sessions created by the removed built-in engine still render. Their metadata types (`pi-web:subagent`, `pi-web:subagent-status`, `pi-web:subagent-result`) are read by `readSubagentRun()` / `readSubagentSessionResources()` in `lib/subagents.ts`, `relation.kind === "subagent"` in `lib/session-reader.ts`, `AgentSessionPanel`, and `GET /api/subagents/[id]`. Only the GET survives: `POST /api/subagents/[id]` (steer/abort) was removed with the engine.
- Agent profile files (`~/.pi/agent/agents/*.md`, project `.pi/agents/*.md`) are shared with `pi-subagents` and other runtimes, so a save round-trips the frontmatter keys this app does not own (`name`, `package`, `allowed_subagents`, `exclude_extensions`, `mutationTools`, …). Managed keys are exactly the pi-subagents spellings `description`, `display_name`, `tools`, `excludeTools`, `extensions`, `subagentOnlyExtensions`, `skill`, `skills`, `skillPath`, `model`, `thinking`, `systemPromptMode`, `inheritProjectContext`, `inheritGlobalContext`, `inheritSkills`, `defaultContext`, `async`, `timeoutMs`, `toolTimeoutMs`, `maxSubagentDepth`, `allowNestedSubagents`, `allowedAgents`, `advertise`, `output`, `defaultReads`, `defaultProgress`, `acceptanceRole`, `aliases`. The editor lives in `AgentsConfig.tsx`, backed by `GET/PUT/DELETE /api/subagents/profiles` and `GET /api/subagents/tools`.
- **Scope shadowing.** Same-name profiles in a higher-precedence scope shadow lower ones: project > workspace > global, per `lib/subagent-profile-precedence.ts`. The panel still lists every configured source and marks shadowed rows "Overridden".
- **`tools` is stored raw.** A save writes every entry verbatim — builtin names, extension and package tool names, `mcp:<server>[/<tool>]`, and path-like selectors — and filters nothing. `tools` omitted (the editor's "inherit default tools" toggle) means the child inherits Pi's default tools; an explicit empty list means no tools. `excludeTools` is the raw deny list, applied after resolution in both cases.
- **`extensions` is a tri-state.** An absent key loads the parent's ambient extensions in a background child, an empty value loads none, and a comma/block list loads exactly those paths. Legacy files written by the removed editor migrate on read: `load_skills`→`inheritSkills`, `load_extensions` (whitelist / `false` / `none`)→`extensions` list or none, `inherit_context`→`inheritProjectContext`, `run_in_background`→`async`, `prompt_mode`→`systemPromptMode`, `disallowed_tools`→`excludeTools`, and the `tools` sentinels `none`→`[]` / `all`/`*`→the builtin 8. A save drops those retired keys: they were ours, pi-subagents ignores them, and keeping them would claim semantics pi-web no longer owns.
- **Enabling is not ours to invent, but the panel now exposes it.** `subagents.agentOverrides.<name>.disabled` owns enable/disable. `lib/subagent-overrides.ts` writes only the user settings file (`<agentDir>/settings.json`, the same path `FileSettingsStorage` derives): disabling sets `disabled: true` on the override entry, enabling deletes that key and prunes an empty entry / `agentOverrides` / `subagents` like pi-subagents' own `enable` action. Everything else in the file survives (JSON read, targeted mutate, atomic write), and the write resolves a symlinked settings path first so dotfile-managed setups keep the link. That writer takes no file lock, matching pi-subagents' own unlocked writer; the lost-update window against SDK `SettingsManager` writes is parity by design, not a bug to fix here. `PUT /api/subagents/overrides` backs the switch on a read-only catalog row; the UI refetches profiles + catalog after a toggle so the row's effective state comes from the catalog's disable ladder, never re-derived. `POST /api/subagents/eject` copies a catalog agent file verbatim into the global or project agent directory (a same-name copy conflicts with 409); the source must be a **builtin or package** file the catalog discovered for that cwd (`user`/`project` scan-dir rows are rejected 400, matching pi-subagents' `handleEject`), and a copy that fails to parse is removed before the error is returned. The tool checkboxes come from `/api/subagents/tools`, which loads the same `createAgentSessionServices()` the models route does and reads `resourceLoader.getExtensions()` — extension tools register at load time, so no session starts. The route caches per cwd for 60 s; `powershell` is filtered out off Windows. MCP enumeration is out of scope.
- **Disable provenance, not file shadowing, drives the lock.** A catalog row's `disabledSource` (`{ scope: "user" | "project"; via: "override" | "bulk" }`) records which settings entry disabled it; it is set whenever the row's effective `disabled === true` and the same-name winner's value is projected onto every shadowed row, because the winner is what the runtime dispatches. `overriddenBy` stays purely file-shadowing provenance. The switch locks only when the user-scope toggle could not undo the disable: `via === "bulk"` at either scope, or a project-scope override. A user-scope override stays switchable — flipping it off removes that override.
