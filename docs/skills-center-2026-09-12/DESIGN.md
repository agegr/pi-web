# Pi Web 技能中心设计文档

实施状态与逐条验收证据：[实施与验收记录](IMPLEMENTATION.md)。设计目标与实现验证状态分别记录。

版本 1.1 · 2026-09-12 · 五大领域修订 · Clear Horizon · Product Design 图稿提案，尚未实施。

本方案与 [PRD](PRD-skills-center.md)、[逐功能 Spec](specs.md)、[接口合同](api-spec.md) 共同构成设计与行为合同。用户已明确：技能中心覆盖计算机、金融、哲学、心理学、玄学五大板块；旧图中的前端设计、代码审查等只属于计算机领域。本修订替代原先以计算机工具为整个中心的设计表达。

## 1. 调整结论

技能中心采用“**领域 → 细分方向 → 技能**”的内容层次，同时保留“发现 / 已安装 / 更新”三类操作视图。这是两个不同维度：领域说明内容归属，操作视图说明用户正在做什么。领域不代表项目/全局安装范围，不改变权限、资源加载或更新方式。

发现首页展示五个领域，五者顺序和视觉权重相同，同时提供全部领域的已收录目录搜索。进入领域后提供该领域的子分类和限定范围搜索。原先的计算机技能卡片移入“计算机领域”，不再占据跨领域首页。已安装和更新默认覆盖全部领域，并提供组合筛选；外部搜索通过独立明确入口进入，不与目录结果混合。

视觉继续沿用已选第三版 Clear Horizon，不为五个领域分别创建五套品牌。金融不强制使用行情图，心理学不变成问诊界面，玄学不使用占卜式全屏装饰；五个板块都采用同一清楚、克制的技能目录界面。

## 2. 领域与细分方向

五大领域由用户确定，以下二级方向为可调整的需求初稿。稳定 ID 和标签配置见 [taxonomy-proposal.json](taxonomy-proposal.json)。该文件没有真实技能归属记录，不是直接上线的市场数据。

| 领域 | 细分方向 | 页面重点 |
|---|---|---|
| 计算机领域 | 前端设计、代码审查、文档工程、测试工程、研究工具 | 原有工程工具完整保留在本领域 |
| 金融领域 | 财务分析、投资研究、风险管理、量化研究 | 展示资料分析和研究工作流的用途 |
| 哲学领域 | 逻辑与论证、伦理学、知识论、哲学史 | 展示概念、论证、文本与思想脉络 |
| 心理学领域 | 认知心理、社会心理、发展心理、研究方法 | 展示心理机制、行为研究和文献方法 |
| 玄学领域 | 易学、命理、风水、塔罗与象征 | 暂按传统术数与象征研究组织，可继续调整 |

“全部领域”是检索范围；“待分类”是元数据状态，两者都不是第六个领域。领域与子分类必须由配置/目录接口提供，不能把所有技能的缺失分类默认成计算机。

跨领域技能允许同时归属多个领域，例如图稿中的量化研究同时属于金融的量化研究和计算机的研究工具。它仍只有一个来源技能身份；在多个领域展示不会重复安装。跨领域统计按每个视图去重，领域分组数量不能简单相加当作总数。

## 3. 信息结构与导航

### 3.1 发现首页

顶部保留 Pi Web、当前项目和返回工作台。页面标题“技能中心”，副标题“跨领域发现、安装与管理 AI 技能”。“发现”被选中后，显示全领域搜索以及五个平级领域入口。

每个领域入口包含名称、一句用途方向、二级方向摘要和“进入领域”。不显示没有真实依据的总技能数量、排行、增长或推荐热度。不把计算机领域用颜色或面积突出成默认中心。

### 3.2 领域内发现

保留操作标签，再增加轻量五领域切换条。面包屑为“全部领域 / 金融领域”等；“全部领域”可返回总览。当前领域标题、简短说明、领域内搜索和二级方向在技能卡片之前。

已收录目录的排序叫“目录顺序”；外部搜索结果叫“源站顺序”，两种数据不能混为一谈。生产文案明确当前结果的覆盖范围，不声称已对整个 skills.sh 市场完成领域分类。

总览搜索默认查询全部领域的已收录目录；不要求先选计算机或其他领域。领域页搜索默认查询当前领域的已收录目录；结果区之后提供“到 skills.sh 外部搜索”次入口，可能位于首屏以下。主动进入外部搜索模式后显示明确来源，并将当前领域、待分类和其他领域的本次结果分组，未分类结果保持可见。两种模式的 query 可沿用，数据和统计必须分开。

分类方向改变时在当前领域内筛选；切换领域时清除失效的子分类，并更新搜索范围说明。返回时恢复原领域、子分类、关键词、滚动与焦点。具体请求规则以 F19–F22 为准。

### 3.3 详情与安装

详情保留来源页面的领域上下文，并在技能标题旁展示完整领域标签。多领域技能可显示多个标签，不复制多份详情记录。领域标签与项目/全局安装标签使用不同分组和说明。

安装面板明确“领域归属”是只读内容信息；真正影响写入位置的选项仍为“当前项目 / 全局配置”。切换领域不允许改变正在执行操作捕获的项目、目标或作用域。

### 3.4 已安装与更新

默认显示所有领域的本地实例或检查结果，避免从金融发现页进入更新后无意隐藏计算机等领域的可更新技能。领域筛选可选择全部、某个领域、待分类；选择具体领域后再展示相关二级方向筛选。与位置、来源、加载状态、模型展示和更新状态组合时采用明确 AND 规则。

清除领域筛选不更改任何技能文件。已分类的共享技能在“全部领域”列表只出现一次物理实例，领域列显示多个标签；若分别安装在不同物理目标，仍保留独立安装实例。多管理绑定的更新歧义仍依原合同阻断，不因分类标签而被忽略。

## 5. 逐页布局与关键交互

### 00 总览

全领域搜索位于五领域入口之前，支持已知技能直接查找；领域入口用于尚不知道具体技能名称的用户。桌面采用五条等宽目录行，手机采用五个纵向入口。每一行明确名称、范围和子方向，主动作“进入领域”。

点击子方向摘要如被实现为链接，必须同时带领域与子分类进入；如果作为纯文本展示则不能伪装成按钮。首次进入无需远程搜索成功才能展示领域结构。分类目录不可用时保留可用搜索入口并说明状态。

### 01 计算机

本页保留原本的 frontend-design、web-guidelines、react-review、文档工程、测试策略和研究工具语境。标题必须是“计算机领域”；前端设计/代码审查等显示在“细分方向”行，而不是与金融、哲学等一级领域并列。

三列结果适合计算机原始六卡密度。技能名称/用途优先，来源和子分类随后，安装标记与动作在稳定位置；未安装主动作统一“安装…”表示先打开确认。

### 09 金融

默认四个方向，示例卡片为财报阅读、行业研究、风险清单和量化研究。量化研究示例展示“金融 / 计算机”两个归属。卡片表达整理资料、定义研究步骤等具体用途，不将领域标签转化成能力或结果保证。

点击财报阅读进入 02，安装进入 03/07。这个非计算机示例用于验证所有技能共用安装机制，不应给金融技能创建另一套安装服务。

### 10 哲学

卡片示例为论证梳理、伦理议题、知识问题、哲学脉络。沿用相同搜索、排序、来源和安装位置，不把哲学内容降级成纯文章页。内容预览仍来自真实 SKILL.md，结构化用途缺失时按合同降级。

### 11 心理学

示例为认知学习、社会行为、发展阅读、研究设计。子分类表达研究与学习任务。保持与其他领域相同的信息密度、入口权重和组件，不额外加入测评、诊断、咨询表单等未提出的功能。

### 12 玄学

示例为易学研读、命理笔记、风水文献、塔罗象征。当前“玄学”解释为传统术数与象征研究，二级方向是可调整初稿。保持中性的资料/方法型界面，不添加占卜动画、运势评分或自动预测等未请求功能。

### 02 详情

返回路径为“全部领域 / 金融领域 / 财报阅读”。名称、领域/子分类、来源和安装状态形成标题区；概览 / SKILL.md / 文件三个标签保留。正文先用途说明和原文中的使用方式，侧栏放来源、相对路径、提交标识。

领域归属应标注可追溯的分类来源，不能伪装成源站认证。“财务分析”是分类，“当前项目已安装”是本地状态，两者不共用一个含糊标签。详情读取/文件安全/快照一致性继续执行 F04/F05。

### 03 安装

桌面为右侧面板，先显示技能与领域归属，再显示项目/全局位置及服务端解析路径。领域标签不可编辑成安装目标。主按钮“确认安装”；提交后阶段为安装中、核验中、明确结果，不画虚构百分比。

全局文案为“写入此主机的全局技能位置”；结果说明“下次资源加载时按当前配置处理”，不承诺任意会话立即可用。运行时关闭视图不取消任务，结果未知先查询核验而不重复写入。

### 04 已安装

桌面紧凑列表新增领域信息；优先将来源放在名称下，位置和加载状态继续独立。示例覆盖计算机、金融、哲学、心理学、玄学五域，以及金融/计算机双归属的量化研究，共六个实例。

“向模型展示”开关只改变提示信息可见性，不是卸载、权限控制或领域开关。统一说明“此设置不禁止手动调用”；只有已加载且按名称可唯一定位的实例才提供具体调用命令。领域未分类的本地技能仍可管理。

### 05 更新

页头包含领域筛选、状态筛选与“检查全部领域”。此动作始终检查当前授权范围内的全部安装实例，不被显示筛选缩窄；筛选只决定结果如何展示。默认全部领域时展示五域的可更新、最新、未检查、失败、不支持等不同状态。

单项更新仍以实例及唯一管理绑定为目标；分类改动不触发重装、更新或文件移动。新归属的技能不应凭分类版本变化就变成“技能内容可更新”。

### 06–08 手机

手机总览必须可发现全部五个领域，不通过水平滑动隐藏后两个主要入口。必要时正文滚动，不强行把所有子分类缩成小字。进入领域后用领域选择器和面包屑替代过长横向栏。

安装为全屏子视图，领域/位置仍分开；底栏保留取消/确认的初始态，运行态调整成关闭视图。已安装使用实例信息块，领域标签在位置之前或之后稳定呈现，搜索和筛选在顶部。

未单独出图的手机领域结果、详情和更新仍按这些规则适配，属于 F16 验收范围，不能因图稿只有三个手机代表页而省略。

## 6. 视觉规范与响应式

复用原有全局 tokens，不按五个领域重配主题色。

| 语义 | 现有 token / 浅色值 | 应用 |
|---|---|---|
| 主背景 | --bg / #ffffff | 页面与列表 |
| 次背景 | --bg-panel / #f5f8fc | 辅助区域与工具栏 |
| 选中 | --bg-selected / #e7efff | 当前领域、标签与作用域选项 |
| 边界 | --border / #dbe3ef | 分隔与控件边框 |
| 正文 | --text / #122342 | 标题、主要信息 |
| 次文字 | --text-muted / #536986 | 来源、路径和说明 |
| 主动作 | --accent / #315bec | 按钮与选中状态 |
| 形状 | --radius-control 6px / --radius-panel 8px | 统一圆角 |

正文 14–16 px，辅助 13 px；图稿尺寸不等于 CSS 字号。主标题约 28 px，领域页标题约 24 px。路径和哈希采用 --font-mono。桌面留白 24–40 px，模块间距复用 8/12/16/24/32 的统一尺度。每个区域保留一个主要蓝色动作。

图标用项目现有图标库；图稿图标是视觉参考，实施不能从图片剪贴图标。成功/警告/错误采用现有语义样式，并同时带文字。深色主题必须继续支持，不能把浅色图逐点采样写成固定样式。

验收宽度 390、768、1280、1440 CSS px；卡片至少保持约 280 px 可读宽度，宽屏 2/3 列、窄屏单列。领域条窄屏转选择器，手机首页领域入口始终全可达。安装面板约 500–520 px，手机全屏；长路径换行、代码区域局部横向滚动，页面不整体横向溢出。

键盘/读屏要求：领域控件、操作标签、分类筛选具备不同 accessible name；焦点可见，返回恢复焦点；错误与状态可被读屏感知，不只依靠颜色；触摸区域建议至少 44 CSS px。弹层焦点限制、Esc 关闭视图和 prefers-reduced-motion 继续按 F16 执行。

## 7. 领域相关状态与文案

| 状态 | 页面表达 | 行为 |
|---|---|---|
| 领域目录暂无记录 | 该领域暂未收录技能 | 保留其他领域与外部搜索入口，不塞示例 |
| 子分类为空 | 该细分方向暂未收录技能 | 返回本领域全部方向 |
| 目录覆盖有限 | 已收录目录 / 当前结果范围说明 | 不声称整个市场所有技能 |
| 外部结果尚无分类 | 待分类 | 不自动归为计算机，不丢弃结果 |
| 一个技能属于多域 | 并列领域标签，详情说明归属来源 | 共用技能身份和安装状态 |
| 分类配置读取失败 | 暂时无法读取领域分类 | 本地管理仍可用，保留未筛选视图 |
| 分类已被移除/改名 | 分类已更新，请重新选择 | 失效筛选回退到明确的全部范围并提示 |
| 从领域进入管理 | 已安装/更新默认全部领域 | 不隐式漏掉其他领域，用户可主动筛选 |
| 安装成功但未加载 | 已写入；下次资源加载时按当前配置处理 | 展示实际加载诊断 |
| 隐藏模型展示 | 此设置不禁止手动调用 | 调用命令仅对唯一已加载实例可用 |

原有首次搜索、无结果、远程错误、未信任项目、重复实例、保存冲突、操作 busy、安装失败、待确认、本地改动、未知基线等状态继续完整实施，具体输入输出与验收见 F01–F18。领域分类不降低原有安装/更新校验。
