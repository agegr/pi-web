## 审阅与实现约束

这些图片用于选择视觉语言及布局，不是功能规格。README 描述、快捷键、额外建议按钮、搜索入口或“在编辑器中打开”等生成内容没有直接纳入产品。实现对照现状清单，保留现有发送快捷键、模型未配置/空输入禁用、工具和资源可用性、Git Diff 条件显示等行为。

细化时特别校正：空会话不是可选会话条目；默认推理不能直接写成高强度思考；模型没配置不能显示为可成功发送；Pi Web 不是仅支持本地模型；复制、压缩、停止、声音、语言/主题与插件等功能必须保留可发现入口。

完成顺序：

1. 用户选定或调整视觉方向。
2. 为 01–20 各输出一张独立设计图，桌面与手机统一样式并逐项核对控件。
3. 整理旧图/新图对照、设计变量、交互变动说明，根据反馈细化。
4. 设计确定后编写按组件拆分的修改计划及验证标准。
5. 在现有 pi-web 上执行计划，保持业务和 API 行为，验证功能与同尺寸视觉效果。

现状基准与原截图完整保留。

## 实装变化

- 白色/冰灰背景、深蓝正文和钴蓝强调；统一字号、按钮尺寸、边框及焦点令牌。
- 项目和 worktree 移至顶栏，侧栏分为会话与文件区域，复用原有状态和操作逻辑。
- 聊天输入整合为一个容器，保留附件、模型、推理、工具、压缩、声音及发送/停止；未配置模型时提供真实配置入口。
- 文件保留多标签、Source / Preview / Diff、引用、下载和自动换行；优化三栏比例，修复源码主题切换冲突。
- 设置、供应商、技能、插件和目录选择统一排版；模型未修改时禁止无效保存。
- 手机布局修复侧栏遮挡和 worktree 越界，验证菜单与输入区域同时可见。
