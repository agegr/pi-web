# 参与贡献 Pi Web

[English](../CONTRIBUTING.md)

Pi Web 是 [pi coding agent](https://github.com/earendil-works/pi) 的轻量网页前端：它和 pi CLI 读写同一个 agent 目录，通过 pi 的 SDK 运行会话。被拒的 PR 大多不是做得不好，而是超出了这个范围，所以开始做新功能之前请先读一下这一页。

## Pi Web 做什么

- **做浏览器比终端更擅长的事。** 按项目浏览会话；查看文件、diff 和工具输出；用表单配置模型、技能、agent、插件和 MCP 服务器，不必手改 JSON；在手机上或局域网里的另一台机器上使用 pi。
- **行为与 pi 一致。** 同一个会话在 Pi Web 和 pi CLI 里表现相同；为 CLI 写的扩展在这里无需修改就能工作，扩展请求的含义以 pi 的 TUI（`@earendil-works/pi-tui`）为准。

## 不在范围内

以下内容无论实现得多好，都不会合并：

- **改变 pi 本身的行为**：系统提示词、工具行为、提示模板展开、重试、压缩，以及写进会话文件的内容。请到 pi 上游提出。
- **可以做成 pi 扩展的功能**：比如定时消息、自定义命令、新的 provider。扩展在 pi 和 Pi Web 里都能用；定时发送就是用扩展解决的，见 [#666](https://github.com/agegr/pi-web/issues/666)。
- **只有 Pi Web 认的配置或扩展 API**：只有 Pi Web 读取的新配置文件；新的 `ctx.ui.*` 选项或 `extension_ui_request` 字段；给现有字段赋予新含义。pi 协议已经表达的东西，怎么显示由网页端自己决定。
- **IDE 或 Git 客户端功能**：编辑文件、文件管理（新建、重命名、删除）、提交历史、第二套 diff 视图。文件查看器保持只读，编辑交给 agent 或你自己的编辑器。
- **新的子系统或运行模式**：定时调度、长期运行的后台 agent、插件或 UI 插槽系统、第二种“精简”模式、多窗格布局。
- **内置主题之外的视觉定制**：自定义主题、皮肤、聊天背景、额外的强调色。外观只能选内置主题（浅色、深色、雾青、蔷薇、松夜、GitHub 浅色/深色、One Half 浅色/深色，或跟随系统），外加少量排版设置。
- **更多的会话管理**：侧栏的会话管理刻意保持精简，只有列表、置顶、归档、重命名、Fork、删除和项目排序。超出这些的想法请先开 issue 讨论。
- **修改 pi 的私有方法或内部状态**：这些在 pi 版本之间随时会变。请向上游申请一个 API。

## 容易合并的改动

- 带有在 `main` 上的复现步骤、并修复根因而不是症状的 bug 修复。
- 不需要新增设置项的小体验改进，尤其是与 pi TUI 行为一致的。
- 更好地渲染 pi 已经产出的内容：工具输出、Markdown、扩展界面。
- 手机、PWA、Windows 和旧版 Safari 的适配修复。
- 附带前后对比数据的性能优化。

## 界面规则

- 同一个信息只显示一次，显示在 pi 产生它的位置。
- 一个好的默认值胜过一个设置项。只有两种选择都很常见时才加开关。
- 顶栏和输入框保持简洁，配置项放到设置里。
- 使用 `app/globals.css` 里已有的主题变量，不要新增颜色。

## 提交 PR 之前

- **做新功能前先开 issue**，说明使用场景。先确认是否合适，可以省掉白做的工作。
- **一个 PR 只做一件事**，不相关的修复请分开提交。
- **修 bug 时写清楚**如何在 `main` 上复现，以及为什么这个改动修的是根因。
- **运行检查**：`npm test`、`node_modules/.bin/tsc --noEmit`、`npm run lint`。开发期间不要运行 `next build`（见 [AGENTS.md](../AGENTS.md)）。
- **新增的界面文字**要同时加上 `en`、`zh-CN` 和 `zh-TW` 三种语言（[国际化](./i18n.md)）。
- **阅读相关的专题笔记**：[AGENTS.md](../AGENTS.md) 列出了代码各部分对应的 `docs/agents/` 笔记，改动哪些文件，就读哪些笔记。
- **尽量不引入新的运行时依赖**；确实需要时请说明理由。

PR 被拒不一定代表这个想法被否定。如果其中有合适的部分，关闭评论会写明是哪一部分，它也常常会在之后以更精简的形式回来。
