# Separate session review from session attachment

Status: proposed. Not implemented; [the design](../session-attachment.md) holds the detail.

Pi Web gives every session two states. **Reviewing** is the default when a session is opened from the sidebar: the transcript is read from its `.jsonl` file and no `AgentSession` exists, so no extension runs and nothing on disk is touched. **Attached** means the session owns its working directory: an `AgentSession` has been created, extensions are loaded, and `session_start` has been emitted with reason `resume` so handlers that reconcile the checkout run exactly as they do in the `pi` CLI. Opening a session never attaches it. Attachment is requested explicitly — by focusing the composer, by the attach action on the session state indicator, or by an extension calling `ctx.switchSession()` / `ctx.newSession()`.

Attachment is guarded in two layers that stay separate. Extensions keep deciding what a session's working state should mean: `session_before_switch` can cancel, and `session_start` performs the checkout, submodule sync, or any other reconciliation. Pi Web decides only whether the working directory is free, using an ownership index keyed by absolute cwd and held alongside the session registry in `lib/rpc-manager.ts`. Both layers are enforced at one choke point, `finishSessionReplacement()`, so sidebar attachment and extension-driven switches cannot diverge. The index observes only sessions owned by this Pi Web process; a `pi` CLI running against the same checkout is not visible to it, and cross-process detection is deferred rather than approximated.

Sessions in different working directories never conflict, and several sessions may attach to one working directory as long as they agree on its state — multiple conversations against a single checkout is a supported workflow, not an error. A conflict is raised only when an attach would change a working directory that another live session is using. The blocked attach is reported with the holding session named, and is resolved by taking over, by giving the incoming session its own worktree, or by staying in Reviewing.

Branch and worktree are reconciled at different times because they are different kinds of state. A branch is a mutation of a fixed directory, so it is reconciled on every attach by the extension's `session_start` handler. A worktree is the identity of the directory itself, recorded in the session file header and frozen before the session exists — services, tools, and project trust are all bound to the cwd before `session_start` is emitted, so no handler can move it. A session's worktree is therefore chosen when the session is created and never changes; `SessionManager.open(path, sessionDir, cwdOverride)` remains a recovery path for sessions whose directory has been removed, not a way to rebind a live session.

Because the extension API exposes no cwd on `ctx.newSession()` or `ctx.switchSession()`, extensions cannot create a session in a different directory, and worktree-per-task remains a Pi Web capability built on `POST /api/agent/new` and `lib/worktree.ts` rather than an extension one.
