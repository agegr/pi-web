# 0004: Windows 系统权限与本地执行安全策略

## 状态
已决策 (Accepted)

## 背景 (Context)
作为一个 AI 面向本地代码库研发的智能体面板，`pi-web` 具有特殊的高级本地能力需求：
1. **任意磁盘文件读写：** 用户在 Web 侧边栏可以切换任意工作区文件夹、递归读取或写入工程代码。
2. **底层 Shell 脚本执行：** 内部的 `@earendil-works/pi-coding-agent` 会直接在宿主系统底层拉起 `bash`、`cmd` 或运行编译器命令去构建、测试、部署代码。

Tauri 默认内置了极度严苛的 **前端网络 / 文件沙箱访问 Scopes 限制**。如果这些磁盘与子进程操作是在 Tauri 框架的 Rust 侧暴露提供给前端，我们需要在 `capabilities.json` 写死极长的白名单权限，且不支持调用机器上任意位置的用户项目代码。

## 决策 (Decision)
我们采用 **隔离沙箱 + 侧后承载 (Sidecar-Delegated Security)** 的安全与执行策略：
1. **零 Rust 系统调用暴离：**
   Tauri 的 Rust 主框架仅作为一个最纯净的 "Browser Box"（窗体外壳）。我们不暴露给 Tauri 前端任何类似 `fs:read` 或是 `shell:execute` 的 Tauri 原生高级指令。
2. **本地高危权限全部委托给 Sidecar：**
   由于我们的 Node.js 伴随进程是一个跑在后台的原生操作系统进程，它本身天生具备最完整的系统执行上下文和极速的 `child_process` / `fs` 操作能力。
3. **保持通信完全物理内循环：**
   Node.js 服务端**仅监听在本地环回地址 (Loopback) `127.0.0.1`**（拒绝任何公网 IP 绑定，杜绝局域网或外部跨站漏洞注入攻击）。Tauri 主界面所有的本地工作区文件浏览、文件写入、以及运行终端 Bash 工具等，都跟运行在浏览器中一样，统一通过底层的 `api/files` 和代理端口进行内循环通信。
4. **提升侧后管理地位：**
   对打包出的 Windows 安装包增设常规的用户运行许可限制。通常以**普通用户身份（Non-Admin）**启动已能安全畅顺跑通一切 Git 提交、文件读取和模型中台交互；只有当检测到用户要求运行系统底层写入时才按需引导提权。

## 后后果 (Consequences)
* **绕过了绝望配置沙箱：** 极大降低了 Tauri 复杂的白名单 Scopes 安全配置门槛。不需要为每一条前端读写文件专门配置 Rust 防护，所有的控制都在成熟的 Node.js 后台承载。
* **100% 的内安全封闭性：** 由于 Next.js 只响应来自本地环回地址（`127.0.0.1`或`localhost`）的请求，且 Tauri 本身限制非同源行为，这构筑了一堵坚不可摧防线。
* **原生开发体验继承：** 我们可以保持我们现有的 NextJS API + RpcManager 架构，不需要对本地读写文件逻辑做任何针对 Tauri 的二次微调开发。
