# pi-web desktop shell

An Electron shell that hosts your pi-web instance in a desktop window,
with a system tray, desktop notifications, and external links routed
to your system browser.

**This app ships no server.** It connects to a pi-web server you run and
host yourself (for example `npm run dev` in your pi-web checkout, or any
deployed instance). The pi-web Next.js app itself is never bundled,
modified, or included here — this directory is a fully self-contained
Electron package.

## Dev workflow

```bash
# in your pi-web checkout: start the dev server (port 30141)
npm run dev

# in this directory
npm install
npm start
```

On first run the shell prompts for your pi-web server URL before the
main window appears. To point `npm start` at a specific server without
typing it, export it as an environment variable:

```bash
PI_WEB_SERVER_URL=http://127.0.0.1:30141 npm start
```

(The first-run dialog still owns persistence; the env var is a
development convenience.)

## Configuration

The server URL is stored in `settings.json` under the app's user data
directory (`app.getPath('userData')`, e.g.
`~/Library/Application Support/pi-web-desktop` on macOS,
`~/.config/pi-web-desktop` on Linux, `%APPDATA%/pi-web-desktop` on
Windows).

- First run: the settings dialog appears before the main window loads.
- Later: **Server Settings…** in the tray menu (or the same dialog from
  the connection-error page) re-edits the URL; saving reloads the window
  at the new origin and persists it.
- If the server is unreachable, the window shows a connection-error page
  with a **Server settings…** affordance.

## Tray

- Closing the main window hides it to the tray (close-to-tray).
- Tray menu: **Show / Focus**, **Server Settings…**, **Quit pi-web**.
- Quit tears down the window and the tray icon — no orphaned processes.

## Security

- Hardened `webPreferences` everywhere: `contextIsolation: true`,
  `nodeIntegration: false`, `sandbox: true`, no `webSecurity`
  relaxations.
- The only bridge into the main process is a minimal preload per shell
  page (`settings:load` / `settings:save` for the settings dialog,
  `error:open-settings` for the failure page).
- `window.open` and `target="_blank"` always open in the system browser;
  in-window cross-origin navigation is delegated to it as well.
- The `notifications` permission is granted only to the configured
  pi-web origin.

## Packaging

One command produces all distributables (mac dmg, linux AppImage, and
the Windows nsis installer configured via
[`electron-builder.yml`](./electron-builder.yml)):

```bash
npm run dist          # electron-builder --mac --linux --win
                      # → dmg + AppImage + nsis in dist/

```

Artifacts land in `desktop/dist/`. The packaged app includes only
`desktop/src` and `desktop/build` — never a pi-web server or `.next`
output.

The placeholder icon set under `build/icons/` is generated by
`node build/gen-icons.js`; rerun that script to regenerate the PNG and
ICNS files.
